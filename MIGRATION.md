# Migration from Kunkun

> Note (2026-09-14): this repository is now **Kuntu**, the shared file &
> storage engine (plan 0066). All crates were renamed `kfs-*` → `kuntu-*`
> (`kfs-index-sqlite` had already become `kfs-index` on the turso migration,
> v0.2.1, and the scan/clean/cloud engine moved in from space-lens as
> `kuntu-scan`). The history below keeps its original commit subjects, so read
> `kfs-*` mentions in quoted subjects as their `kuntu-*` equivalents.

This repository is the extracted file-search workspace of
[kunkunsh/kunkun](https://github.com/kunkunsh/kunkun), preserved with its full
git history.

## Deliberately excluded (they remain in Kunkun)

Parent-only wiring never belonged to the Rust workspace and was not migrated:

- `packages/core/src/file-search/**` — shell-neutral TypeScript service
- `packages/db/helpers/file-search-roots.ts` — root/settings orchestration
- `apps/desktop/electron/file-search/**` and RPC/preload wiring
- `packages/client/src/file-search/contract.ts` and the Hono/OpenAPI routes
- the `pnpm-workspace.yaml` entry pointing at `crates/file-search/crates/kuntu-napi`

## Generated files

`crates/kuntu-napi/index.js` and `crates/kuntu-napi/index.d.ts` are generated by
NAPI-RS (`napi build`) and stay tracked because `main`/`types` resolve to them
before any consumer build. CI regenerates both and fails on a diff; nobody
hand-edits them. Platform binaries (`*.node`) are never committed.

## Post-extraction changes (not in Kunkun history)

- `style`: one `cargo fmt` fix in `crates/kuntu-napi/src/lib.rs` (the Kunkun
  checkout was shared and left untouched; the drift was formatting only).
- `feat(kuntu-index-sqlite)`: monotonic `SCHEMA_VERSION` (`PRAGMA user_version`),
  refused-forward migration for newer databases, and upgrade tests. Kunkun
  databases migrate in place from version 0.
- License, CI, standalone repository metadata and this file.
